# AILO Intent Layer v0.1

## 목적

이 문서는 자비스 메인 브레인에서 AILO가 맡는 역할을 정한다.

AILO는 사용자가 직접 써야 하는 문법이 아니다. 사용자는 자연어로 말한다.

자비스 메인 브레인은 그 말을 AILO식 의도 슬롯으로 정리한 뒤, 실행 가능한 작업 구조로 바꾼다.

## 핵심 정의

```text
사용자 자연어
-> AILO식 의도 슬롯
-> 작업 분기
-> 파일/브레인/스킬/프로젝트 표면
-> 검증 기준
```

## 왜 방향을 유도하는가

범용 모델은 너무 넓게 반응할 수 있다.

AILO는 그 넓은 반응을 작업 목적에 맞게 유도하기 위해 사용자의 말을 아래 조건으로 정리한다.

```text
what to do
what to read
what not to touch
what to produce
where to stop
how to verify
```

목표는 더 많은 말을 만드는 것이 아니라, 다음 행동의 조건을 안정화하는 것이다.

## 최소 슬롯

요청을 처리하기 전에 아래 슬롯을 채운다.

- `verb`: 사용자가 원하는 실제 동작
- `obj`: 다룰 대상
- `goal`: 이번 작업의 목표
- `output`: 남겨야 할 산출물
- `scope`: 이번 턴에서 건드릴 범위
- `source`: 필요한 원천소스
- `rule`: 따라야 할 규칙
- `ban`: 하지 말아야 할 일
- `risk`: 실패 가능성이 큰 지점
- `stop`: 어디서 멈출지
- `verify`: 무엇으로 통과를 확인할지

## 처리 규칙

- 슬롯이 비어도 함부로 채우지 않는다.
- 로컬 문서로 확인 가능한 값은 먼저 로컬에서 찾는다.
- 사용자의 목적과 금지가 충돌하면 멈추고 짧게 확인한다.
- 사용자가 긴 양식을 몰라도 되게 의도 슬롯은 대체로 숨긴다.
- 결과물에는 필요한 만큼만 자연어로 드러낸다.

## 브레인 제작에서의 역할

브레인 제작 요청은 아래처럼 해석한다.

```text
brain_build{
  goal: "어떤 일을 반복해서 맡길 브레인인가",
  output: "폴더, 진입문서, 룰북, 메모리맵, 세션카드, 소환문구",
  scope: "이번 턴에 실제로 만들 범위",
  source: "필요한 원천소스",
  ban: "원천소스 오염, 과복제, 사용자가 긴 양식을 외워야 하는 구조",
  verify: "필수 파일 존재, 재진입 가능, 원천소스와 산출물 분리"
}
```

## 금지

- AILO 이름만 붙이고 실제 슬롯 잠금을 하지 않는다.
- 사용자에게 AILO 문법을 직접 쓰라고 요구한다.
- 슬롯을 많이 만든다는 이유로 구조를 과하게 키운다.
- 검증 기준 없이 실행 결과만 남긴다.

## 한 줄 기준

AILO는 자비스 안에서 `사람 말`을 `실행 조건`으로 바꾸고, 범용 모델의 반응을 목적에 맞게 유도하는 의도 제어층이다.
