# Handoff Prompts v0.2

## 메인 브레인 부팅

```text
부팅해.
BOOT.md부터 읽고, 필요한 파일만 이어서 읽어.
```

## 새 브레인 제작

```text
새 브레인을 만들어줘.

사용자는 긴 양식을 모른다고 가정해.
내 말을 읽고 목적, 산출물, 금지, 필요한 원천소스를 네가 정리해.

브레인 목적:
- <사용자가 자연어로 적는 목적>

원하는 결과:
- Codex에서 바로 부팅 가능한 독립 브레인 폴더
- 새 스레드에 붙일 소환 문구
- 작업 기록 위치
- acceptance test

원칙:
- 필요한 정보가 부족하면 한 번에 핵심만 물어.
- 막히지 않으면 바로 설계하고 만들어.
- `01_Source_Pack`은 원천소스로만 써.
- 현재 작업 기록은 `00_Orchestrator`에 남겨.
```

## 새 스레드 시작 문구

```text
이 스레드는 새 브레인 전용 세션이다.
먼저 START_HERE.md, MAP.md, LOCAL_RULEBOOK.md, MEMORY_MAP.md, SESSION_CARD.md, BOOT.md를 읽는다.
그다음 BRAIN.md와 MODE_REGISTRY.md를 따른다.
원천소스는 SOURCE_BINDINGS.md에 적힌 파일만 우선 확인한다.
부팅 후 현재 브레인의 역할과 받을 수 있는 요청을 짧게 보고한다.
```

## 아주 짧은 사용자 호출

```text
<목적> 브레인 만들어줘.
부족한 건 네가 정리하고, 바로 쓸 수 있게 폴더와 소환문구까지 준비해.
```

## 전문 지식팩 제작

```text
전문 지식팩을 만들어줘.

주제:
- <사용자가 자연어로 적는 주제>

원하는 결과:
- 자료를 바로 쌓는 폴더가 아니라, 다시 읽고 쓸 수 있는 지식팩
- 객체, 개념, 관계, 규칙, 주장, 근거가 분리된 구조
- 처음 읽을 파일과 읽기 순서
- 출처 기록 표면
- 검증 기준

원칙:
- 사용자는 옵션팩 이름을 몰라도 된다고 가정해.
- 필요한 옵션팩은 네가 고른다.
- 원문을 그대로 쌓지 말고 지식 카드와 인덱스로 바꿔.
- 근거 없는 관계는 확정하지 말고 unknown으로 남겨.
```

## 프로젝트 오케스트레이션 세션 시작

```text
이 스레드는 프로젝트 오케스트레이션 세션이다.
프로젝트 BOOT 또는 MISSION 문서를 먼저 읽고, ROADMAP과 ORCHESTRATOR를 확인한다.
메인 브레인 역할을 넘겨받지 말고, 이 프로젝트 범위 안에서만 진행한다.
```
