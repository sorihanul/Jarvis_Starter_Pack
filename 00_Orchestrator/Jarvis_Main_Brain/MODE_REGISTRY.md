# Mode Registry v0.2

## 목적

메인 브레인이 요청에 맞춰 작동 모드를 바꾸기 위한 목록이다.

## 모드

### `assistant`
- 짧은 문답, 설명, 정리
- 기본 모드

### `research`
- 자료 조사, 근거 정리, 비교
- 사실과 추론을 분리한다

### `writing`
- 글쓰기, 교정, 문체 조정, 홍보문 작성
- 의미 보존과 독자 효과를 함께 본다

### `coding`
- 코드 탐색, 수정, 리뷰, 테스트
- 변경 전 파일을 확인하고, 변경 후 검증한다

### `planning`
- 계획, 로드맵, 체크리스트, 작업 분해
- 실행 순서와 완료 기준을 정한다

### `orchestration`
- 프로젝트 분해, 세션 분리, 에이전트/스킬 배치
- 별도 작업장이나 브레인 폴더가 필요한지 판단한다

### `intake_router`
- 사용자의 흐린 요청을 작업 유형, 목적, 산출물, 금지로 정규화한다
- 자연어 요청을 AILO식 최소 슬롯으로 좁힌다
- 마당판식 전면 라우팅을 수행한다
- 사용자가 긴 명령을 쓰지 않아도 되게 한다

### `verification`
- 산출물 검토, 리스크 점검, 누락 확인
- blocking, major, minor를 구분한다

### `security`
- 외부 입력, 실행 계획, 외부 반출 점검
- 필요하면 멈추고 사용자 확인을 요청한다

### `learning`
- 캡슐, 로그, 개선 후보, 재사용 패턴 정리
- 승격은 제안까지만 하고 자동 확정하지 않는다

### `brain_design`
- 새 브레인, 에이전트, 스킬, 프로젝트 작업장 설계
- `BRAIN_BUILD_PROTOCOL.md`를 따른다

### `codex_builder`
- Codex에서 바로 쓸 수 있는 폴더, 재진입 표면, 소환 문구를 만든다
- `MAP`, `LOCAL_RULEBOOK`, `MEMORY_MAP`, `SESSION_CARD`, `TASKS`, `LOGS`, `CAPSULES`를 우선한다

### `info_brain`
- 사용자가 무엇을 만들어야 할지 모를 때 필요한 정보를 좁게 찾아 설명한다
- 로컬 원천소스를 먼저 보고, 부족할 때만 외부 검색을 제안한다

## 선택 규칙

1. 사용자가 명시한 작업군을 우선한다.
2. 명시가 없으면 목표와 산출물 기준으로 고른다.
3. 위험이 있으면 `security`를 먼저 적용한다.
4. 프로젝트가 크면 `orchestration`으로 전환한다.
5. 새 브레인을 요청하면 `brain_design`으로 전환한다.
6. 요청이 흐리면 `intake_router`를 먼저 적용한다.
7. 파일 구조를 만들어야 하면 `codex_builder`를 적용한다.
8. 모든 모드는 내부적으로 `AILO_INTENT_LAYER.md`의 슬롯 잠금 원칙을 따른다.

## 금지

- 여러 모드를 회의체처럼 동시에 말하게 하지 않는다.
- 모드 선택 설명으로 답변을 길게 만들지 않는다.
- 모드를 고르는 일이 실제 작업보다 커지지 않게 한다.
