# Coding Meta Brain

## purpose

`Coding_Meta_Brain` is an experimental coding Chief brain for one case-scoped coding workspace.

It helps an AI coding session separate goal lock, design, implementation, verification, release boundary, and reusable memory export.

## status

```text
experimental_static_ready:true
runtime_validated:false
reference_ready:false
stable_ready:false
```

This brain can be read and tested as a public document harness, but it should not be described as a validated coding runtime yet.

## use when

```text
larger coding task
multi-surface project
frontend/backend/integration split
design and verification separation needed
release boundary important
memory export candidate needed
```

## do not use when

```text
small one-file patch
no role split needed
fast direct edit is enough
validated production automation is required
```

For smaller bounded work, consider `Coding_TOML_Agent_Brain`.

## operating shape

This brain manages:

```text
final goal lock
external research
working behavior contract
critical risk scan
sub-brain selection
thread handoff
verification gate
release boundary
memory export candidate
closeout report
```

## boundaries

- Do not code before the final goal and working behavior are locked.
- Do not collapse design, implementation, and verification into one claim.
- Do not publish operational files as project output.
- Do not promote memory exports as canon without review.
- Do not call this stable until real larger project evidence exists.

## main files

- `START_HERE.md`: human and agent entry point.
- `BOOT.md`: boot contract.
- `BRAIN.md`: identity and non-definition.
- `FINAL_GOAL_LOCK.md`: owner-goal locking rules.
- `WORKFLOW_SEPARATION.md`: design, implementation, verification split.
- `FUNCTION_PACKS.md`: coding operation packs.
- `THREADS/`: sub-brain thread routing and handoff contracts.
- `SUB_BRAINS_LIBRARY/`: optional role-brain templates.
- `REPORTS/`: verification, final report, decision trace, and runbook surfaces.
