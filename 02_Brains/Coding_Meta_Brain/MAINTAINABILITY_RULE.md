# Maintainability Rule

## rule

For non-developer owners, maintainable boring code beats clever code.

Prefer documented, searchable, widely supported, ordinary patterns.

## prefer

```text
common_framework
minimal_dependencies
simple_folder_structure
conventional_names
official_examples
clear_run_and_test_commands
plain_readme
```

## avoid

```text
clever_abstraction
niche_library
custom_auth
premature_microservices
complex_state_system
unnecessary_build_pipeline
undocumented_magic
```

## maintainability check

```text
can_next_AI_understand_from_README:
dependencies_are_minimal:
run_command_documented:
test_command_documented:
major_choices_have_reason:
known_limits_documented:
```
