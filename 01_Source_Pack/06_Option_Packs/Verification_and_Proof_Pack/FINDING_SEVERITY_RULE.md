# Finding Severity Rule v0.1

## 목적

발견한 문제의 심각도를 일정하게 나눈다.

## 등급

```text
blocking:
  목적 달성을 막는다. 완료로 닫으면 안 된다.

major:
  핵심 목적은 일부 가능하지만 실사용에서 실패하거나 혼란을 만든다.

minor:
  핵심 동작은 가능하지만 표현, 연결, 정리 문제가 있다.

note:
  개선 아이디어다. 이번 성공 기준에는 필수는 아니다.
```

## Blocking 예시

```text
필수 진입 파일이 없다.
부팅 경로가 서로 충돌한다.
검증 대상이 무엇인지 알 수 없다.
실행하면 승인 범위를 넘는다.
배포 패키지에 기기 고유 경로가 남아 있다.
```

## Major 예시

```text
문서는 있지만 읽기 순서가 애매하다.
사용 조건이 약해서 잘못 켜질 수 있다.
검증 기준이 있으나 재검증 경로가 없다.
동작은 하지만 결과 보고가 불충분하다.
```

## Minor 예시

```text
표현이 조금 흐리다.
예시가 부족하다.
파일명이 조금 덜 직관적이다.
중복 문장이 있다.
```

## Note 예시

```text
나중에 자동화하면 좋다.
추가 예시가 있으면 좋다.
별도 템플릿을 만들 수 있다.
```

## 출력

```text
finding:
severity: blocking | major | minor | note
evidence:
why_it_matters:
fix_needed:
```
