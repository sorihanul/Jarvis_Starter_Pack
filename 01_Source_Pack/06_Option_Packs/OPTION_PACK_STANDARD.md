# Option Pack Standard v0.1

## 목적

옵션팩은 자비스 본체에 항상 넣기에는 크지만, 특정 요청에서 반복적으로 필요한 능력을 묶은 선택형 패키지다.

## 옵션팩의 정체

옵션팩은 새 브레인, 스킬, 프로젝트 작업장, 검증 절차를 만들 때 붙였다 떼는 능력 단위다.

```text
core brain = 기본 의도 해석과 제작 오케스트레이션
option pack = 특정 조건에서만 켜는 보조 능력
domain pack = 사용자가 자기 목적에 맞게 나중에 만드는 전문 팩
```

옵션팩의 목적은 모델 능력을 늘리는 것이 아니다.

이미 넓게 반응할 수 있는 범용 모델을 더 좁은 작업 조건으로 제한한다.

```text
read less
drift less
leave better artifacts
reuse the result later
```

## 필수 질문

옵션팩을 만들거나 켤 때는 아래 질문에 답해야 한다.

```text
이 팩은 무엇을 더 잘하게 만드는가?
언제만 켜야 하는가?
어떤 입력을 더 확인해야 하는가?
어떤 산출물을 만들어야 하는가?
무엇을 하면 안 되는가?
어디서 멈춰야 하는가?
어떻게 검증하는가?
```

## 필수 파일

각 옵션팩은 최소한 아래 파일을 가진다.

```text
README.md
ACTIVATION_RULE.md
INPUT_SLOTS.md
OPERATING_RULE.md
OUTPUT_CONTRACT.md
STOP_RULE.md
VALIDATION_RULE.md
```

작은 팩은 위 파일을 `README.md` 안에 합쳐도 된다. 다만 읽는 모델이 활성 조건, 입력, 산출물, 중단 기준, 검증 기준을 바로 찾아야 한다.

## 이름 규칙

외부 자료나 배포 프로젝트의 이름을 자비스 능력명으로 그대로 쓰지 않는다.

자료에서 얻은 내용을 자비스식으로 변환했다면 이름도 자비스의 역할 언어로 다시 붙인다.

```text
bad:
  [SourceName] Agent Pack
  [ProductName] Guard

good:
  Capability Import Pack
  Evidence Intake Pack
  Preference Memory Pack
  Source Command Filter Pack
```

실제 사용자가 켜는 팩 이름은 자비스 안에서의 기능을 드러내야 한다.

## 활성 조건

옵션팩은 사용자의 요청이 아래 중 하나에 해당할 때만 켠다.

```text
사용자가 직접 해당 능력을 요청한다.
작업 실패 위험이 명확히 해당 팩의 영역이다.
새 브레인 제작에 해당 팩의 능력이 핵심이다.
외부 자료나 대량 문서를 다뤄 기본 코어만으로는 오염 위험이 크다.
```

## 비활성 조건

아래 경우에는 켜지 않는다.

```text
간단한 질문에 답하면 충분하다.
일회성 작업인데 별도 팩을 읽는 비용이 더 크다.
사용자가 도메인 팩 제작을 요청하지 않았다.
팩을 켜면 컨텍스트가 불필요하게 커진다.
```

## 선택형 팩 설계 원칙

옵션팩은 아래 방향을 따른다.

- 본체는 얇게 두고, 능력은 선택 팩으로 분리한다.
- 기억 쓰기는 하나가 아니라 등급을 나눈다.
- 검색과 최근 회수는 다른 동작으로 본다.
- 사용자 프로필은 무제한 기억이 아니라 예산과 안정도를 둔다.
- 외부 자료는 모델에 넣기 전에 지시 오염을 검사한다.
- 하위 에이전트는 완전한 새 세션이 아니라 제한된 작업 실행자로 다룬다.
- 스킬은 실행 권한과 메모리 권한을 분리한다.
- 큰 자료 묶음은 코드나 문구가 아니라 능력 단위로 흡수한다.

## 출력 계약

옵션팩이 적용되면 결과는 아래 중 하나로 닫는다.

```text
설계 규칙
브레인 제작 보조 규칙
스킬 제작 보조 규칙
프로젝트 작업장 구성 규칙
검증 체크리스트
사용자에게 줄 소환 문구
```

## 검증

옵션팩 적용 후 아래를 확인한다.

- 기본 코어 부팅이 무거워지지 않았는가?
- 옵션팩이 켜지는 조건이 분명한가?
- 외부 의존 없이 패키지 안의 파일만으로 이해되는가?
- 도메인 팩을 기본 스타터에 과적재하지 않았는가?
- 라이선스나 출처 위험이 있는 표현을 그대로 가져오지 않았는가?
- 산출물이 실제 브레인 제작에 도움이 되는가?
