# Jarvis Context Realignment Note v0.1

## 목적

- 세션이 길어져 지금 왜 이 작업을 처리하는지 바로 설명하기 어려울 때, 무엇부터 다시 확인할지 정한다.
- 공개판 작업 표면인 `세션 카드`, `TASKS`, `LOGS`, `CAPSULES`, `프로젝트 작업장`을 어떤 순서로 다시 읽을지 고정한다.

## 언제 읽나

- 같은 세션이 길어져 현재 작업 목적을 바로 말하기 어려울 때
- 새 작업은 아닌데 답변 톤과 판단 기준이 자꾸 달라질 때
- 읽어야 할 문서가 너무 많아져 세션 복귀 속도가 느려질 때
- 프로젝트 기준과 일반 세션 기준이 섞여 어느 표면부터 봐야 할지 바로 정하지 못할 때
- `TASKS`, `LOGS`, `CAPSULES` 중 무엇을 먼저 읽어야 할지 바로 정하지 못할 때

## 한 줄 원칙

- 문서를 더 많이 읽어 해결하려 하지 말고, 얇은 재정렬 표면부터 다시 확인한다.

## `SESSION_CARD` 표면 규칙

- 이 문서에서 `SESSION_CARD`는 개념명이 아니라 현재 세션을 설명하는 실제 문서를 뜻한다.
- 기본 위치는 `TASKS/` 아래의 세션 카드 문서다.
- 프로젝트 세션이면 `TASKS/PROJECTS/<project_id>/` 아래의 세션 카드 문서를 우선한다.
- 새 카드를 만들어야 하면 `TASKS/SESSION_CARD_TEMPLATE_v0.1.md`를 기준으로 작성한다.

## 기본 재정렬 순서

1. `SESSION_CARD`
2. 현재 안건이 적힌 `TASKS/` 문서
3. 현재 안건과 직접 연결된 `LOGS/` 문서
4. `START_HERE.md`
5. `MAP.md`
6. `POLICY.md`
7. 프로젝트 세션이면 `TASKS/PROJECTS/<project_id>/ORCHESTRATOR.md`
8. 필요 시 관련 `AGENTS/` 또는 `SKILLS/` 문서

## 각 표면의 역할

### 1. `SESSION_CARD`
- 이 세션은 누구인가
- 왜 이 세션을 운용하는가
- 어디까지를 이번 범위로 정했는가
- 현재 세션 카드 파일 위치가 어디인가

### 2. 현재 안건이 적힌 `TASKS/` 문서
- 지금 실제로 처리하는 작업은 무엇인가
- 바로 다음에 할 행동은 무엇인가

### 3. 현재 안건과 직접 연결된 `LOGS/` 문서
- 최근 어떤 행동을 실행했는가
- 이미 확인한 실패, 경고, 검증 결과가 무엇인가

### 4. `START_HERE.md`
- 현재 워크스페이스에 다시 복귀할 때 읽는 기본 순서
- 지금 어떤 레이어에서 작업해야 하는가

### 5. `MAP.md`
- 현재 구조를 다시 확인한다
- 세부 문서를 더 읽기 전에 어디에 무엇이 있는지 먼저 확인한다

### 6. `POLICY.md`
- 판단과 실행 경계를 다시 확인한다

### 7. `TASKS/PROJECTS/<project_id>/ORCHESTRATOR.md`
- 프로젝트 세션에서 지금 어떤 순서로 진행하는지 다시 확인한다
- 현재 프로젝트의 단계와 역할 배치를 다시 확인한다

### 8. 관련 `AGENTS/` 또는 `SKILLS/` 문서
- 현재 작업에 맞는 역할 카드와 절차 카드를 다시 고른다

## 3단 재정렬 모드

### 1. Fast Realign

짧게 판단 기준을 바로 설명하지 못할 때:

1. `SESSION_CARD`
2. 현재 안건이 적힌 `TASKS/` 문서
3. 현재 안건과 직접 연결된 `LOGS/` 문서

### 2. Standard Realign

판단 기준을 다시 맞춰야 할 때:

1. `SESSION_CARD`
2. 현재 안건이 적힌 `TASKS/` 문서
3. 현재 안건과 직접 연결된 `LOGS/` 문서
4. `START_HERE.md`
5. `POLICY.md`

### 3. Deep Realign

세션이 길어졌고 구조 파악까지 다시 해야 할 때:

1. `SESSION_CARD`
2. 현재 안건이 적힌 `TASKS/` 문서
3. 현재 안건과 직접 연결된 `LOGS/` 문서
4. `START_HERE.md`
5. `MAP.md`
6. `POLICY.md`
7. 프로젝트 세션이면 `TASKS/PROJECTS/<project_id>/ORCHESTRATOR.md`
8. 필요 시 관련 `AGENTS/` 또는 `SKILLS/` 문서

## 금지

- 판단 기준이 자꾸 바뀐다고 문서를 과도하게 읽지 않는다
- `LOGS/` 전체를 처음부터 끝까지 다시 읽지 않는다
- 세션 카드 없이 현재 안건만 보고 바로 판단하지 않는다
- 맵 없이 세부 문서를 바로 읽기 시작하지 않는다
- 프로젝트 세션인데 `TASKS/PROJECTS/` 작업장을 건너뛰지 않는다

## 세션 카드와의 관계

- `SESSION_CARD`는 정체성 카드다
- 이 문서는 재정렬 순서 카드다
- 둘은 겹치지 않는다
- 필요하면 `TASKS/SESSION_CARD_TEMPLATE_v0.1.md`를 기준으로 카드를 새로 만들거나 갱신한다

즉:
- `SESSION_CARD` = 이 세션은 누구인가
- `TASKS`의 현재 안건 문서 = 지금 무엇을 처리하나
- `JARVIS_CONTEXT_REALIGNMENT_NOTE` = 판단 기준을 바로 설명하기 어려울 때 무엇부터 다시 확인하나

## 추천 사용 문장

- "컨텍스트 재정렬부터 해."
- "Fast realign 하고 계속 진행해."
- "Deep realign 하고 다시 판단해."

## 한 줄 결론

- 재정렬은 더 많은 기억을 읽는 일이 아니라, 얇고 강한 표면부터 다시 확인해 판단 기준을 맞추는 일이다.
